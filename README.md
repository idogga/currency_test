# Основные положения

Набор сервисов для управления пользователями и валютами:

- `PersonService` — API пользователей и выдачи JWT.
- `FinanceService` — API финансовых данных и валют.
- `CurrencyScheduler` — загрузка курсов валют с сайта ЦБ РФ.
- `DbMigrator` — создание и обновление схем баз данных.

## Требования

- Docker Desktop с Docker Compose v2.
- .NET 8 SDK для запуска тестов.
- Доступ в интернет для загрузки Docker-образов и обращения планировщика к сайту ЦБ РФ.

## Запуск приложений

Из корневой папки репозитория выполните:

```powershell
docker compose -f ./deploy/docker-compose.yaml up --build
```

## Получение валют через OData

`FinanceService` предоставляет список валют по адресу `http://localhost:8081/odata/Currencies` при запуске через Docker Compose. Для локального запуска сервиса используйте адрес и порт из профиля запуска. Эндпоинт требует JWT: сначала получите токен через `POST http://localhost:8080/api/users/login`, затем передавайте его в заголовке `Authorization: Bearer <JWT>`.

В запросах доступны поля `Id`, `Name`, `Rate`. Поддерживаются параметры `$select`, `$filter`, `$orderby`, `$count`, `$expand` и `$top`; максимальное значение `$top` — 100. Примеры ниже можно выполнять в REST Client для VS Code:

```http
@financeUrl = http://localhost:8081
@token = <JWT>

### 1. Получить все валюты
GET {{financeUrl}}/odata/Currencies
Authorization: Bearer {{token}}

### 2. Найти валюты с курсом выше 50 рублей и отсортировать по убыванию курса
GET {{financeUrl}}/odata/Currencies?$filter=Rate gt 50&$orderby=Rate desc
Authorization: Bearer {{token}}

```

# Допущения
- Решение запускается локально или в тестовом окружении с помощью Docker Compose. Учётные данные PostgreSQL и JWT, указанные в конфигурации, предназначены только для разработки и не должны использоваться в production.
- При первом запуске PostgreSQL создаются базы `users` и `financy`, после чего `DbMigrator` применяет миграции. Скрипт начальной инициализации PostgreSQL выполняется только при создании пустого Docker volume. Если базы уже созданы, изменение `init-db.sql` само по себе их не пересоздаст.
- `PersonService`, `FinanceService` и `CurrencyScheduler` подключаются к общей базе PostgreSQL, но используют разные базы данных согласно конфигурации.
- Для получения курсов валют требуется доступ к `www.cbr.ru`. Планировщик запускает загрузку при старте и ежедневно в 10:00 UTC. Для временных HTTP-сбоев настроены повторные запросы; если загрузка всё же завершается ошибкой, ошибка записывается в лог. Постоянное наблюдение за логами и оповещения в решении не настроены.
- У планировщика прописаны в коде cron-строка для запуска обновления. В реальном проекте, это должно быть вынесено в переменную.
- Расписание Hangfire и blacklist JWT хранятся в памяти. После перезапуска состояние памяти теряется. Поэтому конфигурация рассчитана на один экземпляр каждого сервиса; для нескольких экземпляров понадобятся общее хранилище фоновых задач и общее хранилище состояния авторизации и ключей.
- Интеграционные тесты создают собственные временные контейнеры PostgreSQL через Testcontainers. Для их запуска необходим работающий Docker, но предварительно запускать сервисы через Docker Compose не требуется.
- Работа с конфигурациями построена через 2 подхода, гибкое получение через IConfiguration и IOptions. Сделано для показа различных вариантов использования. В реальном проекте, должно быть унифицировано.
- Курсы хранятся без истории: при обновлении запись перезаписывается. Ключ сопоставления — название валюты, полученное от ЦБ; предполагается, что оно стабильно и уникально. ISO-код валюты в текущей модели не используется.
- Для получения курса используется значение `VunitRate` из ответа ЦБ. Планировщик запрашивает данные для текущей даты UTC, но расписание публикации курсов определяется ЦБ; в выходные и праздники дата актуального курса может отличаться от запрошенной. Дата курса отдельно в таблице не сохраняется.
- В конфигурации есть прямые порты сервисов и отдельный Nginx на порту 80. Предполагается, что локальная разработка обращается к сервисам напрямую; использование Nginx требует проверки настроенных маршрутов.
